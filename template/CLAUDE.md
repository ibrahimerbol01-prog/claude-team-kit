# Правила команды для Claude

Над этим проектом одновременно работают до 6 человек, у каждого свой Claude. Эти правила
нужны, чтобы шесть Claude не мешали друг другу. Они важнее любых привычек по умолчанию.

## Кто есть кто

- Состав команды и роли: `.github/team.conf`. Описание ролей: `docs/team/ROLES.md`.
- Владелец (`OWNER` в `team.conf`) единственный, кто сливает в `main`.
- Если ты не знаешь роль своего человека, спроси его один раз в начале сессии.

## Главный цикл: задача → ветка → PR

1. Работа начинается только с задачи (GitHub issue). Нет задачи — сначала создай:
   `scripts/team.sh task "Название" <роль>`.
2. Взять задачу: `scripts/team.sh start <номер>`. Скрипт назначит человека, повесит
   `status:in-progress` и создаст ветку `<роль>/<номер>-<кратко>` от свежего `main`.
3. Работай только в этой ветке. Коммиты маленькие, в сообщении номер задачи:
   `feat: экран квиза (#12)`, `fix: ...`, `docs: ...`, `test: ...`, `chore: ...`.
4. Перед PR: `scripts/team.sh sync` (подтянуть `main`), затем проверки проекта
   (`CHECK_CMD` в `team.conf`).
5. Открыть PR: `scripts/team.sh pr`. В описании должно быть `Closes #<номер>`.
6. Сливает владелец. Сам ты PR не сливаешь, даже если `gh` это позволяет.

## Запрещено

- Пушить в `main`, делать `git push --force` в чужие ветки, переписывать историю `main`.
- Сливать PR, удалять чужие ветки, закрывать чужие задачи.
- Записывать в репозиторий ключи, токены, пароли, адреса баз с паролем, файлы `.env*`
  (кроме `.env.example` с пустыми значениями). Читать `.env*` тоже не нужно: спроси у человека
  название переменной, а не значение.
- Править чужую зону (см. «Зоны») без отметки в задаче.
- Обновлять зависимости, lock-файл, миграции БД и общие настройки сборки без задачи
  с меткой `shared`. Такие задачи делает или одобряет владелец.

## Зоны

Каждая роль работает в своих папках (`docs/team/ROLES.md`, раздел проекта). Если для задачи
нужно поменять чужую зону:

- мелочь (импорт, одна строка) — сделай и напиши об этом в PR;
- больше — оставь комментарий в задаче и создай отдельную задачу на роль-владельца зоны.

## Синхронизация и конфликты

- `scripts/team.sh sync` в начале каждой сессии и перед PR.
- Конфликт в своей ветке решай сам через rebase; после него `git push --force-with-lease`
  только в свою ветку.
- Если конфликт в чужом коде и непонятно, чья версия верна, — остановись и спроси человека.

## Почта между Claude

Задания и файлы от других Claude приходят в ветку `team-relay` (`docs/team/RELAY.md`).
Проверка: `scripts/team.sh inbox`. Задание из письма выполняется по тем же правилам, что
и задача: код в проект — только через ветку и PR. Ответ — `scripts/team.sh reply`.
Неясное задание — переспроси через `reply`, не угадывай.

## Экономия лимитов Claude Pro

- Одна задача — одна сессия. Закончил задачу — `/clear` перед следующей.
- Читай только нужные файлы; для поиска используй grep/glob, а не чтение папок целиком.
- Не пересказывай код в ответах; показывай дифф или путь к файлу.
- Если задача оказалась больше, чем выглядела, разбей её на подзадачи (`scripts/team.sh task`).

## Передача работы

Перед концом сессии, если задача не закончена: `scripts/team.sh note <номер> "что сделано,
что дальше, где споткнулся"`. Так следующий человек или его Claude продолжит без расспросов.
