# Работа владельца

Ты помогаешь владельцу (`OWNER` в `.github/team.conf`). Только он сливает в `main`.
Проверь это: `gh api user --jq .login` должен совпасть с `OWNER`. Если нет — этот навык
не для этой сессии, переходи к навыку `team-task`.

## Разбить идею на задачи

1. Уточни: идея в 2–3 предложениях, срок, кто в какой роли (`team.conf`, `docs/team/ROLES.md`).
2. Сначала сценарий демо из 5 шагов (`docs/team/HACKATHON.md`). Задачи выводятся из него.
3. Задачи по 1–4 часа. У каждой: роль, результат, «готово, когда», файлы.
4. Разведи файлы: две задачи в работе одновременно не должны править один файл.
   Где не получается — одна задача ждёт другую, напиши это в обеих.
5. Первые задачи backend — контракт данных, первые задачи frontend — экраны на заглушках,
   чтобы роли не ждали друг друга.
6. Покажи таблицу, после «ок» создай: `scripts/team.sh task "Название" <роль> "описание"`.
   Описание — по шаблону задачи: что сделать, готово когда, файлы.

## Доска

`scripts/team.sh board`. Сообщи коротко:
- что слито с прошлого раза;
- `status:blocked` — кто застрял и что разблокирует;
- PR, которые ждут больше часа;
- свободные роли без задач — предложи им задачи.

## Разбор PR

Для каждого открытого PR (`gh pr view <n>`, `gh pr diff <n>`, `gh pr checks <n>`):

1. Проверки зелёные.
2. Есть `Closes #n`, задача существует.
3. Дифф в зоне роли автора; чужие зоны отмечены в описании.
4. Нет секретов: ищи в диффе `key`, `token`, `secret`, `password`, `sk-`, `eyJ`, адреса баз
   с паролем, файлы `.env*`. Нашёл — не сливать, попросить удалить и сменить ключ.
5. Нет зависимостей, lock-файла, миграций без метки `shared`.
6. Ветка свежая (`gh pr view <n> --json mergeStateStatus`); `BEHIND`/`DIRTY` — попросить
   автора сделать `scripts/team.sh sync`.

Итог: таблица «PR — вердикт — что поправить» и порядок слияния (сначала маленькие
и те, от которых зависят другие). Сливай только после «ок» владельца по каждому PR:
`scripts/team.sh merge <n>`. После серии слияний напомни всем `scripts/team.sh sync`.

## Сломанный main

Если после слияния `main` не собирается: найди виновный коммит (`git log --oneline -5`)
и предложи на выбор быстрый откат (`git revert <коммит>` в ветке `lead/<номер>-revert`,
затем PR) или срочную правку. Пока `main` красный — новые PR не сливаются.

## Финал

- Заморозка: перестань сливать функции, только `type:bug` с меткой `demo`.
- Прогон демо на свежем `main` по сценарию; проблемы — задачи с меткой `demo`.
- Финал: тег (`git tag v1.0 && git push origin v1.0` — после «ок»), деплой, проверка ссылки.

## Диспетчер в паре Claude

Если владелец диктует задания Claude другого участника (`docs/team/RELAY.md`): режь цель
на задания на одну сессию, у каждого — цель, входные файлы, что вернуть, «готово, когда».
Покажи список, после «ок» отправляй по одному (`scripts/team.sh send`), жди ответ
(`scripts/team.sh inbox --wait=15`), проверяй результат и файлы, затем следующее задание
или уточнение.

## Ключи

Ключи раздаются лично, вне репозитория. Если участник просит ключ в задаче или PR —
напомни правило и не вставляй значение никуда.
